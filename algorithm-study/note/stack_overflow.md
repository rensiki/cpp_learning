## 스택 오버플로우와 BSS 세그먼트

### 먼저 메모리 구조부터

프로그램이 실행될 때 메모리가 이렇게 나뉩니다:

```
높은 주소
┌─────────────────┐
│      Stack      │  ← 함수 호출, 지역변수 (보통 1~8MB 제한)
├─────────────────┤
│       ↓         │
│                 │
│       ↑         │
├─────────────────┤
│      Heap       │  ← new, malloc (수백MB 가능)
├─────────────────┤
│      BSS        │  ← 전역/static 변수 (초기화 안 된 것)
├─────────────────┤
│      Data       │  ← 전역/static 변수 (초기화 된 것)
├─────────────────┤
│      Text       │  ← 실행 코드
낮은 주소
```

---

### 스택 오버플로우란?

함수가 호출되면 **지역변수가 Stack에 올라갑니다.**

Stack은 OS가 보통 **1~8MB로 제한**합니다.

```cpp
void solve() {
    int dp[1000000]; // 4MB → 스택 터짐 💥
}
```

`int` 하나가 4바이트니까 `1,000,000개 = 4MB` → Stack 한도 초과 → **Segmentation Fault**

재귀가 너무 깊어도 마찬가지입니다. 함수 호출마다 스택 프레임이 쌓이기 때문입니다.

---

### 전역변수는 왜 괜찮나?

전역변수는 Stack이 아니라 **BSS/Data 세그먼트**에 올라갑니다.

BSS는 Stack처럼 엄격한 크기 제한이 없고, **프로세스 전체 메모리 한도**(보통 256MB~)까지 쓸 수 있습니다.

```cpp
int dp[1000000];      // 전역 → BSS, 4MB → 문제 없음 ✅

void solve() {
    int dp[1000000];  // 지역 → Stack, 4MB → 터짐 💥
}
```

---

### 힙(Heap)은?

`vector`나 `new`로 할당하면 **Heap**에 올라갑니다. Heap도 BSS처럼 큰 메모리를 쓸 수 있습니다.

그래서 지역변수로 큰 배열이 필요하면 이렇게 해도 됩니다:

```cpp
void solve() {
    vector<int> dp(1000000); // Heap에 할당 → 안전 ✅
    // 또는
    int* dp = new int[1000000]; // Heap → 안전하지만 해제 필요
}
```

---

### 정리

| 선언 방식 | 저장 위치 | 크기 제한 | 비고 |
|-----------|-----------|-----------|------|
| 함수 안 배열 | Stack | ❌ 1~8MB | 크면 터짐 |
| 전역 배열 | BSS/Data | ✅ 넉넉함 | 알고리즘에서 자주 씀 |
| vector / new | Heap | ✅ 넉넉함 | 동적 할당 오버헤드 약간 있음 |

**→ 알고리즘에서 큰 배열은 전역으로 선언하는 게 관례인 이유가 바로 이것입니다.**
