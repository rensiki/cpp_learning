직접 구현 vs 라이브러리

C++ STL 이분탐색 라이브러리
cpp// 값이 존재하는 위치
lower_bound(arr, arr+n, target)  // target 이상인 첫 위치
upper_bound(arr, arr+n, target)  // target 초과인 첫 위치

// 예시
arr = [1, 3, 5, 7, 9]
lower_bound → 7의 위치 반환
upper_bound → 9의 위치 반환 (7 초과 첫 번째)

언제 라이브러리, 언제 직접 구현?
라이브러리로 충분:
  ✅ 정렬된 배열에서 값 탐색
  ✅ 특정 값의 존재 여부 확인
  ✅ 특정 값의 개수 세기 (upper - lower)

직접 구현 필수:
  ❌ 매개변수형  →  f(x) ≤ K 인 최대 x  (이번 문제)
  ❌ 정답 이분탐색  →  검증 함수가 복잡할 때
  ❌ 실수 범위 이분탐색  →  부동소수점 오차 처리 필요

실전 판단 기준
"탐색 대상이 배열인가?"
        │
       YES → lower/upper_bound 고려
        │
       NO  → 직접 구현
cyan 후반~blue부터는 직접 구현 비중이 압도적으로 높아져.
라이브러리는 보조 도구고, 결국 직접 구현이 기반이야.

결론
지금처럼 직접 구현 원리를 익히는 게 맞는 방향이야. 라이브러리는 원리를 이해한 후에 쓰면 강력한 도구가 되지만, 원리 없이 쓰면 엣지케이스에서 반드시 막혀.
