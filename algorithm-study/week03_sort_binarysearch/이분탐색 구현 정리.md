## 이분탐색 구현 구조 총정리

//태민: 현재 예시는 목표 값보다 작은것 중 최대를 구하는 거라고 볼 수 있음
"조건을 만족하는 것 중 최대" 를 찾는 전형적인 패턴

이분탐색 2대 패턴
거의 모든 이분탐색 문제는 이 둘 중 하나야:
패턴 1: 조건 만족하는 것 중 최대   ← 이 문제
        "X엔으로 살 수 있는 가장 큰 N"

패턴 2: 조건 만족하는 것 중 최소
        "X를 넘기 위한 가장 작은 N"
코드 차이는 딱 한 줄이야:

패턴 1 (최대)
if (f(mid) <= X) { ans = mid; lo = mid+1; }  // 가능하면 저장 후 오른쪽
else               hi = mid-1;

// 패턴 2 (최소)
if (f(mid) >= X) { ans = mid; hi = mid-1; }  // 가능하면 저장 후 왼쪽
else               lo = mid+1;
탐색 방향만 반대로 뒤집히는 거야.


//태민: 만약 특정 값이 존재하는지 확인하는 문제면 마지막에 결과값이 해당 특정 값과 동일한지 비교만 하면 될듯

## 구조는 사실 3가지

### 구조 A - "ans 따로 저장"
```cpp
lo = 0, hi = 1e9, ans = 0;
while (lo <= hi) {
    mid = (lo + hi) / 2;
    if (가능) { ans = mid; lo = mid+1; }
    else        hi = mid-1;
}
// 정답: ans
```

//태민: 



### 구조 B - "lo 수렴"
```cpp
lo = 1, hi = 1e9;
while (lo < hi) {
    mid = lo + (hi-lo+1) / 2;
    if (가능) lo = mid;
    else      hi = mid-1;
}
// 정답: lo (== hi)
```

### 구조 C - "hi 수렴" (B의 쌍둥이)
```cpp
lo = 1, hi = 1e9;
while (lo < hi) {
    mid = (lo + hi) / 2;       // 내림
    if (불가능) hi = mid;      // hi를 mid로 수렴
    else        lo = mid+1;
}
// 정답: lo (== hi)
```

구조 B는 **"가능한 값 중 최댓값"** 탐색  
구조 C는 **"불가능한 값 중 최솟값 - 1"** 탐색 → 같은 문제를 반대로 접근

---

## 장단점 비교

| | 구조 A | 구조 B/C |
|---|---|---|
| **직관성** | 낮음 (lo-1이 답?) | 높음 (lo==hi가 답) |
| **실수 포인트** | ans 초기값 설정 | 올림/내림 mid 선택 |
| **종료 조건** | `lo <= hi` | `lo < hi` |
| **범위 초기값** | 더미값 필요 (0 등) | 실제 후보값으로 설정 |
| **유연성** | 높음 (뭐든 적용 가능) | 구조 고정 필요 |

## 근본적인 의의

세 구조 모두 결국 같은 걸 표현해:

```
가능  가능  가능  가능 │ 불가능  불가능  불가능
                      ↑
                    이 경계를 찾는 것
```

**경계를 어느 쪽 시각으로 찾느냐**의 차이일 뿐이야.

```
구조 A: 경계 왼쪽 값을 ans에 직접 기록하며 찾음
구조 B: lo를 경계 왼쪽으로 수렴시킴
구조 C: hi를 경계 왼쪽으로 수렴시킴 (불가능 최솟값 탐색)
```

---

## 실제로 뭘 써야 하나

**입문/실전 모두** → 구조 A 추천

이유는 단 하나야:

> 올림/내림 mid를 **고민할 필요가 없다**

구조 B/C는 직관적으로 보이지만, `(hi-lo+1)/2` 를 언제 쓰는지 헷갈리는 순간 무한루프가 나고, 대회 중 디버깅이 어려워. 구조 A는 실수해도 ans 초기값만 점검하면 돼서 **오류가 단순**해.

결국 가장 중요한 건 구조 선택이 아니라 **불변식을 머릿속에 유지하는 것**이고, 그게 익숙해지면 세 구조 모두 자유롭게 쓸 수 있어.
